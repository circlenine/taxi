つけ待ち台帳

セットアップ手順書

アプリを自分のアカウントで公開するまでの、全部の手順。パソコンのブラウザだけで終わります。黒い画面（コマンド）は一切使いません。

この順番でやります（全部で40分ほど）
  1. データの置き場所を作る（Supabase）
  2. アプリのファイルを置く（GitHub）
  3. アプリに「データの置き場所」を教える
  4. 公開する（Vercel）
  5. 公開したURLをSupabaseに登録する
  6. 勝手に登録されないように閉める
  7. ログインする人を作る
  8. ちゃんと動くか確かめる
  9. これまでのデータを取り込む
はじめる前に GitHub・Vercel・Supabase の3つのアカウントと、Supabaseのプロジェクトができていることが前提です（前の手順書のぶん）。 できていなければ、先にそちらを終わらせてください。
それと、この資料の入っているフォルダの中にある「アプリ本体」フォルダを、デスクトップなど分かりやすい場所に置いておいてください。途中で使います。
途中で分からなくなったら 無理に進めず、その画面のスクリーンショットを撮って送ってください。中途半端に押して進むより、止まって聞くほうが早く終わります。 やり直しは何度でもできます。壊れることはありません。

1データの置き場所を作る約5分

記録をしまう「棚」を、Supabaseの中に作ります。長い呪文を貼り付けて実行ボタンを押すだけです。中身を理解する必要はありません。

  1. 「アプリ本体」フォルダの中の supabase フォルダを開き、schema.sql をメモ帳で開きます。
    （ファイルを右クリック →「プログラムから開く」→「メモ帳」。Macなら右クリック →「このアプリケーションで開く」→「テキストエディット」）
  2. 開いたら Ctrl + A（Macは ⌘ + A）で全部選んで、Ctrl + C でコピー。
  3. ブラウザで Supabase を開き、左メニューの SQL Editor をクリック。
  4. New query を押すと、大きな入力欄が出ます。そこをクリックして Ctrl + V で貼り付け。
  5. 右下の Run を押す。（Ctrl + Enter でも実行できます）
成功のサイン画面の下に Success. No rows returned と緑色で出ます。これが出れば完了です。赤い文字が出たら、何も触らずスクリーンショットを送ってください。
記録をしまう棚と、「ログインした人だけが読み書きできる」という鍵のルールができました。

2アプリのファイルを置く約8分

アプリの部品（11個のファイル）を、GitHubという保管庫に置きます。ここに置いたものが、次のステップで自動的にインターネットに公開されます。

  1. ブラウザで github.com を開いてログイン。
  2. 右上の ＋ マーク → New repository をクリック。
  3. Repository name に tsukemachi と入力。
  4. その下の Private を選ぶ。（自分だけが見られる設定です）
  5. いちばん下の Create repository を押す。
  6. 次の画面に uploading an existing file という青いリンクがあるので、それをクリック。
  7. 「アプリ本体」フォルダを開いて、中身のファイルを全部選んで、ブラウザの点線の枠の中にドラッグ＆ドロップします。
    （フォルダを開いて Ctrl + A で全選択 → そのままドラッグ）
  8. ファイル名がずらっと並んだら、下の Commit changes を押す。
ここが一番間違えやすい 「アプリ本体」というフォルダごとドラッグすると、あとで真っ白な画面になります。 フォルダを開いて、中のファイルを選んでドラッグしてください。

アップロード後の画面に index.html app.js style.css などが直接並んでいればOK。 アプリ本体 というフォルダが1個だけ表示されていたら、やり直しです（その場合は、そのフォルダ名をクリックして中に入り、同じようにアップロードし直すか、連絡をください）。
GitHubの画面に、index.html を含む11個のファイルと supabase フォルダが並んでいます。

3アプリに「データの置き場所」を教える約6分

アプリは、自分のデータがどこにあるかをまだ知りません。Supabaseから2つの文字列をコピーして、アプリに教えます。

3-1　Supabaseから2つコピーする

  1. Supabaseを開き、左メニューのいちばん下 Project Settings → API をクリック。
    （新しい画面では Data API という名前のこともあります）
  2. Project URL という欄の https://〇〇〇〇.supabase.co をコピー。横のコピーボタンが便利です。
  3. メモ帳に貼って、いったん置いておきます。
  4. 同じ画面の anon または publishable と書かれた長い文字列もコピーして、メモ帳に貼ります。
間違えてはいけないもの 同じ画面に service_role という、赤字で「秘密」「Never share」と注意書きのあるキーがあります。 こちらは絶対に使いません。コピーもしないでください。間違えて使うと、URLを知った誰でも記録を全部消せる状態になります。 使うのは anon／publishable の方だけです。

3-2　アプリに書き込む

  1. GitHubの tsukemachi の画面に戻り、ファイル一覧から config.js をクリック。
  2. 右上のほうにある鉛筆のアイコン（Edit this file）をクリック。
  3. 下のほうに2行あります。ダブルクォート " の内側だけを書き換えます。
    window.SUPABASE_URL = "ここにProject URL"; window.SUPABASE_ANON_KEY = "ここにanonキー";
  4. 右上の Commit changes... → 出てきた箱の Commit changes を押す。
よくある失敗 クォート " を消してしまう／前後に余計な空白が入る／URLの最後に / を足してしまう。この3つが原因のほぼ全てです。 貼り付けたあと、行の見た目が最初と同じ形（= "……";）になっているか確かめてください。
アプリが、自分のデータの置き場所を知っている状態になりました。

4公開する約5分

GitHubに置いたファイルを、インターネットから見られるようにします。

  1. ブラウザで vercel.com を開いてログイン。
  2. Add New... → Project をクリック。
  3. GitHubのリポジトリ一覧が出ます。初回は Install や Adjust GitHub App Permissions を求められるので、案内に従って許可してください。
  4. 一覧から tsukemachi を見つけて Import を押す。
  5. 設定画面が出ますが、何も変えずにそのまま Deploy を押す。
    （Framework Preset が Other になっていればOK。環境変数の入力は不要です）
  6. 1〜2分待つと、紙吹雪とともに完成画面が出ます。Continue to Dashboard をクリック。
  7. Domains のところに https://tsukemachi-〇〇〇.vercel.app というURLがあります。これをコピーしてメモ帳に貼ってください。これが台帳のアドレスです。
この時点で開いてもログインできません まだアカウントを1つも作っていないので、それで正常です。ログイン画面が出ることだけ確認できれば十分です。
インターネット上にアプリが置かれ、ログイン画面が表示されます。

5公開したURLをSupabaseに登録する約3分

「このアドレスからのアクセスは本物です」とSupabaseに教えます。これを飛ばすと、パスワード再設定のメールが使えません。

  1. Supabase → 左メニュー Authentication → URL Configuration。
  2. Site URL の欄に、さっきコピーしたURL（https://tsukemachi-〇〇〇.vercel.app）を貼って Save。
  3. Redirect URLs の Add URL を押し、URLの最後に /login を足したものを貼って保存。
    https://tsukemachi-〇〇〇.vercel.app/login
パスワードを忘れたときの再設定メールが、正しく戻ってくるようになりました。

6勝手に登録されないように閉める約2分

初期状態では、URLを知った人が自分でアカウントを作れてしまいます。入り口を閉めます。

  1. Supabase → Authentication → Sign In / Providers。
  2. 一覧の Email をクリックして開く。
  3. Allow new users to sign up のスイッチをオフにする。
  4. Confirm email はオフのままでOK。
  5. Save を押す。
これでURLが外に漏れても、アカウントを持っていない人は中身を一切見られません。記録も、グラフも、金額も。

7ログインする人を作る約6分

7-1　アカウントを作る（人数ぶん繰り返す）

  1. Supabase → Authentication → Users。
  2. 右上の Add user → Create new user。
  3. その人のメールアドレスと、仮のパスワード（6文字以上）を入力。
  4. Auto Confirm User にチェックを入れる。ここを忘れるとログインできません。
  5. Create user を押す。
  6. 残りの人のぶんも、同じように作ります。

7-2　自分を管理者にする

管理者になると、メンバー一覧を見たり、他の人の記録を直したりできます。

  1. Supabase → SQL Editor → New query。
  2. 下の2行を貼り付け、メールアドレスのところだけ自分のものに書き換えて Run。
    update public.profiles set is_admin = true where id = (select id from auth.users where email = 'ここに自分のメール');
仮パスワードの伝え方 他の人に仮パスワードを伝えるときは、初回ログイン後にすぐ自分で変えてもらってください。 変え方は「管理」画面にあります（使い方マニュアルを参照）。
全員ぶんのログインができ、自分は管理者になりました。

8ちゃんと動くか確かめる約5分

上から順に試してください。6つ全部通れば完成です。

  • 公開URLを開くと、ログイン画面が出る
  • 作ったアカウントでログインできて、台帳が表示される（右上に自分の名前が出る）
  • 1件記録してみると、「記録した（時間単価 ¥◯◯/h）」と出る
  • 別のアカウントでログインすると、さっきの記録が見える。ただし「直す・消す」のボタンは出ない
  • 管理者のアカウントで右上の 管理 を押すと、メンバー一覧が出る
  • ログアウトしてから公開URLを開き直すと、ログイン画面に戻される
4つめが重要です 「他の人の記録は見えるけれど、直す・消すのボタンが出ない」——ここが出ていれば、鍵のルールが正しくかかっています。 もし他人の記録に「消す」ボタンが出ていたら、そのアカウントが管理者になっているか、手順1が途中で失敗しています。連絡をください。

9これまでのデータを取り込む約5分

スプレッドシートに貯めてきた記録を、まとめて移します。

  1. 台帳にログインし、一覧・書き出し タブを開く。
  2. いちばん下の「スプレッドシートから取り込む」の入力欄に、スプレッドシートで範囲を選んでコピーしたものを、そのまま貼り付けます。見出しの行も一緒で構いません。
  3. 年が書かれていない日付（5/21 のような形）がある場合は、横の「年」の欄を合わせます。
  4. 中身を確かめる を押す。
  5. 読めた件数・すでに同じ記録がある件数・読めなかった件数が出ます。表の中身を見て、日付と金額が合っているか確かめてください。
  6. 問題なければ この◯件を取り込む を押す。
安心して試せます 「中身を確かめる」の段階では、まだ何も保存されていません。おかしければ貼り直せば済みます。 また、同じ記録を二重に取り込むことはない仕組みなので、途中で失敗して貼り直しても増えません。

取り込んだ記録は、操作した人の名義で入ります。3人ぶんが混ざったシートなら、それぞれが自分のぶんだけを貼ってください。
以上で完成です 公開URLをスマホで開き、ホーム画面に追加しておくと、アプリのように使えます（やり方は使い方マニュアルに書いてあります）。 日々の使い方・困ったときの対処は、同じフォルダの他の資料を見てください。
