つけ待ち台帳　開発側メモ

引き継ぎで渡すもの／渡さないもの

この資料だけ、作った側（古里）が見るためのものです。本人に渡す必要はありません。

渡すもの

渡すもの渡し方補足
この一式（zip）LINE・メールどちらでも解凍してデスクトップに置いてもらう。「アプリ本体」フォルダを手順の途中で使う。
自分の連絡先
詰まったときのスクショ送り先		口頭／LINE「分からなくなったら押さずに送る」を先に合意しておく。これが一番効く。
作業する時間の約束口頭40分。細切れだと途中で迷子になるので、まとまった時間を取ってもらう。
渡す必要がないもの Supabase の Project URL と anon キーは、本人が自分の画面から見る手順にしてあります。 こちらが預かって伝える必要はありません。公開URLも、本人がVercelで取得します。

渡してはいけないもの

渡さないもの理由
service_role キーこれ1つで全データの消去・書き換えができる。アプリにも持たせていない。手順書では「コピーもしない」と明記済み。
Database Password同上。本人が紙に控えて本人だけが持つ。
各サービスのログインパスワード渡す理由も受け取る理由もない。
メール・SMSの確認コードアカウントを丸ごと明け渡すのと同じ。

引き継ぎ後に、こちら側で外すもの

本人が自分で設定を終えたあと、開発中に持っていたアクセス権を落とします。本人に以下を依頼してください。

  • Supabase → 組織の Team から、古里のアカウントを削除してもらう（開発中に Administrator で招待していた場合）
  • Vercel に自分のアカウントで入っていたら、ログアウトしておく

自分の側では、テスト用に作った Supabase プロジェクトと Vercel プロジェクトを削除し、ローカルに置いた config.js（本番の値が入っているもの）を消しておきます。

当日の進行（画面共有する場合）

本人が一人で進める前提の資料ですが、不安がるようなら30分だけ画面共有で伴走するのが確実です。その場合の配分。

時間やること
0-5分全体像の説明。「棚を作る → ファイルを置く → 公開する → 鍵をかける」の4つだけだと伝える。
5-15分手順1〜2。GitHubのアップロードだけ見届ける。ここが唯一、間違えると後で詰まる箇所。
15-25分手順3〜6。config.js の貼り付けと、サインアップを閉じるところ。
25-30分手順7〜8。アカウント作成と動作確認6項目。ここまで通ったら離れてよい。
手を出さない 代わりに操作すると、次に同じ場面が来たとき本人が止まります。 「どこを押すか」だけ言って、押すのは本人に徹してください。Vercelの無料プランは1人しか入れない仕様なので、どのみち代わりには操作できません。

構成のメモ

置き場所中身
Vercel静的サイト（ビルドなし）。GitHubにpushすると自動で再デプロイ。
GitHub本人所有のPrivateリポジトリ。Hobbyプランは共同編集ができないので、こちらからpushはできない。修正時はファイル内容を渡して本人に貼り替えてもらう。
SupabasePostgres + Auth。RLSで「ログイン済みなら全件読める／自分の記録だけ書き換えられる／管理者は全部」。supabase/schema.sql は再実行しても壊れない。
キーの扱いconfig.js に URL と anon キーを直書き。anon キーはブラウザに載る前提の公開値で、守りはRLS側。service_role はどこにも置いていない。
将来、自動同期を頼まれたら スプレッドシートからの自動取り込みは Apps Script で可能だが、重複防止のために rides に source_key 列と一意制約を足す必要がある。 ただし二重管理になるので、入力はアプリ・集計はCSV書き出しの一方向を勧める。
